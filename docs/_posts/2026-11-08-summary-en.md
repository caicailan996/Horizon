### [Apple Discloses HALO Humanoid System Using Two Qwen Models](https://weibo.com/1642634100/RqjjGllvw) ⭐️ 8.0/10

Apple researchers submitted an arXiv preprint on November 4 disclosing HALO, a three-layer autonomous control system for humanoid robots, and validated it on a Unitree G1 by transferring actions learned in simulation to unfamiliar real rooms. The upper layer uses Qwen3.6-35B-A3B for task orchestration, the middle layer uses Qwen3.5-2B for motion generation, and the bottom layer is a reinforcement-learning-trained action tracker. The team has released code for data generation, model training, and deployment.

telegram · zaihuapd · Nov 7, 13:35

**「Background」** Humanoid robot autonomy has been constrained by a data bottleneck: mapping pixels and free-form language to low-level joint commands requires paired supervision, and no sufficiently large corpus of such data existed, so some approaches relied on human teleoperation and wearable capture. HALO instead generates egocentric vision-language-motion data entirely in simulation and then runs the resulting policy fully onboard the physical robot.

**「Impact」** Robotics developers can examine and reuse the released data-generation, training, and deployment code to replicate the HALO stack on a Unitree G1, though the paper remains a preprint and the source does not specify license or repository details.

### [GitHub Rubicon Handles 7,200 Pushes per Second](https://github.blog/engineering/architecture-optimization/inside-githubs-new-git-storage-architecture/) ⭐️ 8.0/10

GitHub introduced Rubicon, a new Git storage architecture designed for large numbers of AI agents concurrently operating on a single repository. In internal tests, it supported 5,000 agents working together and processed 7,200 push operations per second while keeping read latency low. The architecture stores Git objects in Azure Blob Storage, manages reference state via Ref-CAS, and uses virtual replicas for reads and writes with background nodes compacting data. Rubicon is currently in limited private preview and will be expanded gradually.

telegram · zaihuapd · Nov 7, 14:12

**「Background」** A Git push updates both object data and branch or tag references, so supporting many simultaneous pushes to one repository requires separating object storage from reference updates and providing enough read/write capacity to avoid contention.

**「Impact」** Teams planning multi-agent coding workflows on GitHub cannot adopt this architecture yet unless they are in the private preview; existing repositories remain on the current storage system until GitHub expands access.

### [Amutable OS Overview: Default Without Shell, SSH, Interpreters](https://lwn.net/Articles/1105934/) ⭐️ 7.0/10

Lennart Poettering, Michael Vogt, and Joaquim Rocha published a technical overview of the planned Amutable Operating System \(AOS\), an image-based Linux OS. The design specifies that nodes will have no UNIX shell, no SSH remote access, and no language interpreters such as Python or Perl by default, and that only images with Verity signatures from keys in the Verity keyring may be activated. The overview describes an announced architecture rather than a shipped distribution.

rss · LWN.net · Nov 7, 09:32

**「Background」** Image-based Linux OSes distribute complete signed system images and update them atomically rather than managing individual packages, which makes cryptographic verification and restrictive defaults easier to enforce. The Amutable overview applies that model to remove common attack surfaces before an operator enables them.

**「Impact」** If adopted as described, administrators would not be able to log in via SSH or run shell or interpreted scripts on AOS nodes, so routine debugging, automation, and packaging would need to happen through the image build and signed update process instead.

### [Pointer Networks vs OR-Tools on TSP: Speed and Scaling Limits](https://www.reddit.com/r/MachineLearning/comments/1xqgg4v/combinatorial_optimization_with_pointer_networks/) ⭐️ 6.0/10

A Reddit user benchmarked Pointer Networks trained with REINFORCE against OR-Tools Guided Local Search with a 10-second timeout on 2D Euclidean TSP instances from N=20 to N=200. The post reports that the neural model produces near-optimal tours in fractions of a millisecond but that solution quality degrades significantly as problem size increases. The author attributes this scaling limitation to the LSTM encoder imposing an artificial sequential order and recency bias on permutation-invariant coordinate sets.

reddit · r/MachineLearning · /u/an2ancan · Nov 7, 20:44

**「Background」** Pointer Networks are sequence-to-sequence models that generate outputs by pointing to input elements, making them applicable to variable-size combinatorial problems like TSP. REINFORCE is a policy gradient reinforcement learning algorithm used here to train the model without supervised optimal solutions.

**「Impact」** For developers evaluating neural combinatorial optimizers, the benchmark suggests that straightforward Pointer Network/LSTM encoder approaches are unlikely to replace OR-Tools for larger TSP instances and that permutation-invariant encoders may be required to mitigate order bias.

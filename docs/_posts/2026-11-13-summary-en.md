### [Rust 1.100 stabilizes never type, allocators, Cargo dependency checks](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 9.0/10

Rust 1.100.0 was released on November 12, 2026. The release stabilizes the never type \(\`\!\`\) and core parts of the \`Allocator\` API. Cargo now warns about unused dependencies by default via \`cargo::unused\_dependencies\`, supports minimum publish age configuration for dependency cooldowns \(RFC 3923\), and uses an existing lockfile in a crate tarball for \`cargo install\`, making \`--locked\` a no-op.

hackernews · mbStavola · Nov 12, 18:39 · [Discussion](https://news.ycombinator.com/item?id=50472038)

**「Background」** The never type is the bottom type for expressions or functions that never return, and custom allocators allow applications and libraries to control memory allocation. Cargo is Rust&\#x27;s package manager and build system, where dependency resolution previously lacked built-in unused-dependency warnings and publish-age controls.

**「Impact」** Projects upgrading to Rust 1.100 will receive Cargo warnings for unused dependencies by default, configurable via \`cargo::unused\_dependencies\`. The \`cargo install --locked\` flag is now a no-op because the crate&\#x27;s existing lockfile is used automatically, so scripts relying on the old behavior may need review.

**「Community Discussion」** Commenters praised the release and highlighted additional stabilized APIs omitted from the blog post, including \`bool::toggle\`, \`Box::map\`, \`str::trim\_prefix\`, \`str::trim\_suffix\`, and \`Path::trim\_prefix\`. One commenter asked whether proper tail calls \(\`become\`\) are included, and the thread did not provide an answer.

### [UMAP 0.6 Adds Faster Search, Recursive Init, New Optimizers](https://www.reddit.com/r/MachineLearning/comments/1xudaah/umap_06_new_initialization_new_optimizers_and/) ⭐️ 8.0/10

UMAP 0.6 has been released with faster nearest-neighbor search, a new recursive initialization, and new optimizers. The author reports neighbor search is roughly 4x faster via PyNNDescent, a seeded 3 million-paper arXiv run finishes in under 5 minutes versus 52 minutes for a single-threaded UMAP 0.5 run, and the new optimizer/initialization path is reproducible with a fixed seed while using all cores. The improvements are opt-in via compatibility\_layout=False because they change the layout, and future versions will make them the default.

reddit · r/MachineLearning · /u/lmcinnes · Nov 12, 13:51

**「Background」** UMAP is a widely used unsupervised dimensionality-reduction method that constructs a nearest-neighbor graph and optimizes a low-dimensional embedding with attraction and repulsion forces. Previous releases initialized with spectral methods or PCA and were tuned for a limited range of repulsion strengths, which limited convergence and quality on million-scale data.

**「Impact」** Users who adopt compatibility\_layout=False can get faster large-scale embeddings and deterministic multi-core runs, but outputs differ from UMAP 0.5; pipelines that depend on exact existing layouts should test before the new behavior becomes the default.

### [Chinese team builds stable thorium-229 nuclear optical clock](https://www.nature.com/articles/s41586-026-11122-1) ⭐️ 9.0/10

Researchers at Tsinghua University have built and stably operated the world&\#x27;s first nuclear optical clock, using thorium-229 nuclear energy-level transitions as the timing reference. The clock relies on a self-developed 148-nanometer continuous-wave vacuum-ultraviolet laser and a thorium-229-doped calcium fluoride crystal, and the work was published in Nature. The team says the device could become a next-generation time-frequency standard for high-precision applications such as satellite navigation and deep-space exploration.

telegram · zaihuapd · Oct 8, 05:19

**「Background」** Conventional optical clocks timekeep by measuring electron transitions in atoms, but their accuracy is limited by environmental perturbations. A nuclear optical clock instead uses the transition between nuclear energy states, which is far less sensitive to external fields; thorium-229 is unique among known nuclides in having a nuclear isomer that can be driven by a vacuum ultraviolet laser, making it the only practical candidate for a solid-state nuclear clock.

**「Impact」** If replicated and validated independently, the thorium-229 nuclear clock could offer a more stable time-frequency reference than existing atomic clocks and improve timing accuracy for satellite navigation and deep-space missions, though the published result remains a first laboratory demonstration rather than a deployed system.

### [Whistle: 16.9 MB Speech-to-Text Model with Accuracy Trade-offs](https://cactuscompute.com/blog/whistle) ⭐️ 6.0/10

Whistle is a speech-to-text model weighing just 16.9 MB, enabling local processing on resource-constrained devices without cloud dependency. However, accuracy is significantly lower than larger models: in one community test, Whistle correctly transcribed 70 out of 170 messages while Qwen ASR \(1.7B parameters\) got 168 correct. The model also lacks streaming output during recording, and some users report it occasionally gets stuck repeating a default phrase like &quot;Thank you.&quot; Whistle is available now as an open-source tool.

hackernews · gmays · Oct 8, 16:59 · [Discussion](https://news.ycombinator.com/item?id=50008427)

**「Background」** Whistle is a speech-to-text model built on Cactus Compute&\#x27;s Needle runtime, which the company previously used for small on-device language models. It operates locally without sending audio to the cloud, supporting 7 languages and processing up to 30-second clips of 16 kHz mono audio in a single pass.

**「Impact」** Developers targeting very small edge devices—such as repurposed smart displays or microcontrollers—may benefit from Whistle&\#x27;s tiny footprint, but they must accept substantially lower accuracy and the absence of live streaming transcription. The model is unsuitable for general-purpose dictation or meeting transcription; it may suffice only for constrained command-and-control scenarios where occasional errors are tolerable.

**「Community Discussion」** Community members compared Whistle with models like Qwen ASR and Parakeet, reporting that Whistle&\#x27;s word error rate is much higher and that it sometimes emits a single phrase repeatedly for long stretches. Several commenters noted the lack of streaming output as a key limitation for live applications. One user successfully integrated Whistle into a hacked Echo Show for local home automation, but only after adjusting expectations for accuracy.

### [Kernel swap cache slot decoupling debate remains unresolved](https://lwn.net/Articles/1098399/) ⭐️ 6.0/10

LWN reports that the Linux kernel&\#x27;s swap layer still directly ties swap cache slots to persistent swap file space, a binding that can cause highly inefficient resource use and has not yet been fixed in mainline. Two competing patch sets aim to decouple the two, but neither is close to being merged, and a lengthy developer discussion shows no consensus on the best path forward. The article is a status report on an ongoing design debate rather than a description of a shipped capability.

rss · LWN.net · Oct 8, 13:43

**「Background」** The Linux swap subsystem uses a swap cache that maps virtual memory pages to slots in a persistent swap file or partition. Currently each cache slot is tightly coupled to a specific swap file location, which can waste resources when cached pages are evicted but the swap space remains reserved. This binding has been a known inefficiency that previous kernel changes addressed only partially.

**「Impact」** Until one of the competing approaches reaches the mainline, systems using persistent swap files can continue to experience the inefficiency caused by the current slot-to-space binding. Developers following the swap subsystem should expect further design discussion rather than an immediately adoptable fix.
